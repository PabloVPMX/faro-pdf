# Seguridad

No adjuntes documentos privados, credenciales ni datos financieros en issues.
Para errores normales, usa un PDF sintético y una descripción reproducible.

Si identificas una vulnerabilidad que pueda exponer datos, utiliza la opción
privada de reporte de vulnerabilidades de GitHub si está disponible. Si no
lo está, abre un issue solicitando un canal privado sin incluir el exploit
ni datos sensibles.

El proyecto está en una etapa inicial y no ofrece un plazo de respuesta
garantizado. Mantén copias de tus documentos. El borrado incremental de
texto no es una redacción segura de información confidencial.
